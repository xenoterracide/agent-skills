# gh-pr-wait Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace output-hygiene's blocking watch pattern with background-shell wake-ups and a one-line `gh pr checks` poll script.

**Architecture:** A POSIX-ish bash script polls `gh pr checks --json --jq` (exit 8 = pending) until terminal, printing one line and exiting 0/1/2. SKILL.md rule 3 moves to background shells with the tail inside the call; gh waits route through the script. The Maven bullet gains `-B`.

**Tech Stack:** bash + gh (no jq — gh's `--jq` does the filtering), node:test with a stubbed `gh` on `PATH`.

**Spec:** `docs/superpowers/specs/2026-11-05-output-hygiene-watch-design.md`

## Global Constraints

- Plugin stays dependency-free: script uses gh + coreutils only; test uses node core modules only.
- Every commit follows output-hygiene rule 2 — redirect hook output, tail only on failure.
- New files carry SPDX headers: the script (`*.sh`) gets MIT; the TypeScript test gets GPL-3.0-or-later, written exactly as `.config/git/hooks/heal.sh` and `scripts/heal.test.ts` carry theirs.
- Work happens on a worktree branch, never `develop`.
- Conventional commit types must pass the commit-msg hook.
- Before the PR: ask the user whether to bump `26.11.2` → `26.11.3` in `.kimi-plugin/plugin.json` and `package.json`.

## Review Focus

- Cancelled checks (bucket `cancel`) are neither fail nor pending — they must land in `fails` or the loop never exits. Test: fake line ` canceled\t` → `fail: canceled`, exit 1 (pins the script's half; the jq half is pinned by the expression in Task 1 and live runs).
- gh errors and check failures both exit 1 — only the tab in gh's output separates them. Test: fake `1|-` with stderr → stderr forwarded, exit 1.
- Old bash (macOS 3.2) + `set -u` + empty forwarded args — `"${args[@]}"` on an empty array is unbound. Test: run with no positional args at all.
- A PR with no checks: gh exits 0 with empty output. Test: fake `0|-` → `pass`, exit 0.
- `--interval`/`--timeout` must never reach gh. Test: fake records its argv; assert neither flag appears.

### Task 1: `gh-pr-wait.sh` with stubbed-gh tests

**Files:**

- Create: `skills/output-hygiene/scripts/gh-pr-wait.sh`
- Test: `scripts/gh-pr-wait.test.ts` (runs under `vitest run scripts`, part of `pnpm test`; TypeScript — maintainer ruling: tests are TypeScript, `.mjs` only for directly-executed files)

**Interfaces:**

- Produces (Task 2 consumes): `skills/output-hygiene/scripts/gh-pr-wait.sh [--interval SECONDS] [--timeout SECONDS] [gh pr checks args...]`; prints exactly one line — `pass`, `fail: name1, name2`, or `pending after 30m: name1, name2`; exits 0 pass, 1 fail or gh error, 2 still pending after `--timeout` (default 1800), 64 usage. Poll interval defaults to 10 s. Fails fast the moment any check bucket reads `fail` or `cancel`.

- [ ] **Step 1: Write the failing tests — harness contract + six cases**

  Harness (pinned — the stub emulates what gh-with-`--jq` emits, one queue entry per invocation, `exit|stdout`; a successful render always prints the line, all-pass is a bare tab, so `-` means no stdout — a gh error; missing lines repeat the last; exit codes are recorded but carry no meaning in JSON mode; the stub always writes `fake gh stderr` to stderr and appends its argv to `$GHW_STATE/argv`):

  ```mjs
  // per case: mkdtempSync state dir, write queue file, write fake-gh:
  #!/bin/sh
  n=$(cat "$GHW_STATE/seq" 2>/dev/null || echo 0); n=$((n + 1)); echo "$n" >"$GHW_STATE/seq"
  entry=$(sed -n "${n}p" "$GHW_STATE/queue"); [ -n "$entry" ] || entry=$(tail -n 1 "$GHW_STATE/queue")
  echo "$@" >>"$GHW_STATE/argv"; echo "fake gh stderr" >&2
  code=${entry%%|*}; out=${entry#*|}
  [ "$out" != "-" ] && printf '%s\n' "$out"
  exit "$code"
  ```

  Cases (all spawn the real script with `--interval 0`, `PATH` prepended with the fake dir, `GHW_STATE` set):

  1. `pass-after-pending`: queue `8|\tbuild`, `0|\t` → stdout `pass`, exit 0, gh called exactly twice (`seq` reads 2).
  2. `fail-fast-while-pending`: queue `8|build\t` → stdout `fail: build`, exit 1, gh called once.
  3. `cancelled-counts-as-fail`: queue `8|canceled\t` → `fail: canceled`, exit 1, one call.
  4. `gh-error-vs-failure`: queue `1|-` → exit 1, stderr contains `fake gh stderr`.
  5. `timeout`: queue `8|\tbuild`, `--timeout 1` → exit 2, stdout matches `/^pending after \d+m: build$/`.
  6. `no-positional-args-and-no-flag-leak`: queue `0|\t`, no args besides `--interval 0` → `pass`, exit 0; recorded argv starts `pr checks --json name,bucket` and contains neither `--interval` nor `--timeout`.
  7. `failure-from-line`: queue `0|build\t` → `fail: build`, exit 1, one call — gh exits 0 but the line names failures; state comes from the line.
  8. `multi-name-separator`: queue `0|build,lint\t` → `fail: build, lint`, exit 1 — comma-space, so names containing spaces stay readable.

- [ ] **Step 3: Implement `gh-pr-wait.sh`**

  Bash, `set -u`, MIT header. Flag loop keeps `--interval`/`--timeout` (both validated numeric, else usage to stderr + exit 64) out of `args`, which forwards everything else verbatim. Poll:

  ```bash
  line=$(gh pr checks ${args[@]+"${args[@]}"} --json name,bucket --jq "$jq" 2>"$err")
  ```

  with `err=$(mktemp "${TMPDIR:-/tmp}/gh-pr-wait.XXXXXXXX")`, `trap 'rm -f "$err"' EXIT`, and this expression, verbatim:

  ```text
  (map(select(.bucket == "fail" or .bucket == "cancel") | .name) | join(",")) + "\t" + (map(select(.bucket == "pending") | .name) | join(","))
  ```

  Decision table — split the line on the first tab into `fails`/`pending`; `fails` comma-joined by jq, printed `${fails//,/, }` (comma-space, so names containing spaces stay readable). In JSON mode gh exits 0 on any successful render, so the line — not the exit code — carries the state. A tab in the line means gh spoke checks; no tab means gh itself errored:

  | condition                                        | action                                                     |
  | ------------------------------------------------ | ---------------------------------------------------------- |
  | no tab in line                                   | `cat "$err" >&2`, exit gh's code (gh error, not a failure) |
  | `fails` nonempty                                 | `fail: <names>`, exit 1 (fail-fast)                        |
  | `fails` empty, `pending` nonempty, pre-deadline  | `sleep "$interval"`, re-poll                               |
  | `fails` empty, `pending` nonempty, past deadline | `pending after $((timeout / 60))m: <pending>`, exit 2      |
  | `fails` empty, `pending` empty                   | `pass`, exit 0                                             |

  Deadline: `deadline=$(( $(date +%s) + timeout ))`, checked after each pending poll.
